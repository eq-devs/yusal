# Üisal 语音住宅设计与造价架构升级计划

2026-11-25 · 研究与设计稿 · 客户端 cae4334，后端 9f8cae4

## 交付目标

房主在手机上开启一次对话，说出住宅要求并看到满足硬条件的可编辑方案。之后可以用日常方位选中对象、测量净距、试改局部、切换视角、比较造价，最后将确认版本交给施工方。第一条贯穿场景用 10 × 13 米单层平屋顶、南向入口、两卧、主卧至少 16 m²。地块、尺寸与币种属于项目数据；用户说话和阅读所用的语言独立处理。

## 研究基线

- 项目已有 55 个公开语音动作、79 个底层命令，部分职责重叠。design.command 连接两者。小模型处于旁路，通用命令和完整设计描述排除在其专用调用范围外。
- 服务端 dialog.brief 已收集整屋意愿，客户端 EngineSession.transaction 已提供单次历史提交和批内失败全退。实时语音会话的撤销分组与该事务语义不同：当前逐条执行，失败跳过后续，先前成功动作可以已经生效。
- 客户端每批动作回传结果和重新构造的屏幕上下文，正常结构包括场景和实体；客户端和网关当前上限均为六批。首次响应、引擎执行和播报需要分别计时。现有 Go 网关已有工具筛选、耗时与 token 记录。
- 前次实验中，指定南入口时，10 × 13 米前三个候选有两个符合，6 × 7 米前三个均不符合。模板上按坚戈估价和默认语音计价分别产生 24,837,372 ₸、335,679 元。预算一致性、硬约束和版本检查是功能验收项。
- 本次实跑仓库 test/perf/engine_bench.dart，macOS ARM64、Dart 3.13.3、JIT，20 次预热后 100 次均值。两个户型分别为两层 16 房和两层 72 房。这组结果测引擎，未包含 Flutter 构建、栅格、音频或网络。

| 单次操作（ms） | 16 房 | 72 房 |
|---|---:|---:|
| 全屋几何冷推导 | 1.691 | 2.324 |
| 已有几何上的估价 | 0.214 | 0.197 |
| 移轴并推导拖动预览 | 1.719 | 3.998 |
| 切分空间并推导拖动预览 | 1.874 | 10.843 |
| 挖出房间并推导拖动预览 | 1.840 | 10.748 |

同一份 AOT 可执行文件两次在 largePlan.run → executeCommand → editDrawnWall 发生 SIGSEGV，均为退出码 134；JIT 同一输入完成。根因待隔离。复现入口为 app 目录下 dart compile exe test/perf/engine_bench.dart -o /tmp/uisal-bench，再执行该二进制。先缩小到最少墙段与具体命令，记录 SDK/系统架构，在 Flutter profile/release 的真实编辑路径复核，再决定代码或 SDK 修复。尚无手机端崩溃率数据。

## 模块边界与一次提交

| 所在位置 | 职责 | 可复用基础 |
|---|---|---|
| Flutter 对话及视图 | 连续聆听、打断、候选高亮、尺寸线、视角和视觉差异 | VoiceSession、局部编辑工具、2D/3D/漫游 |
| Go 语音网关 | 从语句生成意图、澄清、能力协商、受控回退；记录匿名耗时与结果 | dialog.brief、已开放工具列表、现有模型适配器 |
| Dart 房屋引擎 | 对象解析、毫米几何、约束评估、预演、事务、撤销 | HouseDocument、EngineSession、DesignHistory、既有楼层和房屋缓存 |
| 预算与分享 | 从指定图纸与价目版本计算工程量、阶段差价，生成冻结的发布快照 | estimateCost、地区价格库、快照仓库与访问控制 |

1. 用户说“只挪厨房和客厅之间的墙段 300 mm，主卧保留 16 m²”。网关返回结构化动作、参照关系和单位。项目长期要求存入本地图纸扩展；对话草稿保留来源和待确认项。
2. 客户端用稳定对象 ID 与当前版本定位；模型所见短别名只在当前场景有效。多个匹配先高亮。只读操作在本地执行；选择、测量、看图不污染撤销记录。
3. 从基准图纸创建内存预演，复用命令与事务逻辑。输出受影响对象、实际尺寸、净面积、约束结果及可选费用差额。遇到不满足的硬条件，保留原项目；返回可重试的原因。
4. 简单且可逆的单步改动可按原有交互直接应用；复合试改或用户说“先看看”时保留候选。确认前检查 projectId、baseRevision 和 operationId；同一操作重复到达只提交一次。手改、撤销、切项目都会使不再适用的结果失效。旧版工具协议保留原路径。
5. 提交后一次刷新历史、画面与自动保存；保存失败沿用可见失败状态与重试。应用被关闭时按最后持久化的版本恢复。施工发布走独立授权，快照只包含对外约定的设计与计价字段；私人笔记、实际支出等单独列白名单。服务器对同一发布键去重。

## 工具优先级

| 批次 | 房主说的话 | 必要的能力与验收 |
|---|---|---|
| 第一批 | “找厨房和客厅之间的墙，量这段净长” | locate、measure。入口方向与屏幕方向分开，凹形房间用选定墙段或真实边界；输出单位、测量两端与尺寸线。 |
| 第一批 | “就挪这一段，隔壁别动。站到门口看看。” | edit_wall_segment、view。调用局部墙命令，检测连带影响；相机切换保留原编辑选区与楼层。 |
| 第二批 | “外轮廓固定，主卧至少 16 平，走廊尽量短。” | 明确 hard/preference；生成、局部修改和重开项目均检查实际净面积。无解时说明当前搜索范围及待放宽条件。 |
| 第二批 | “比较两套，把门窗差价指给我看。” | preview_change、compare 和工程量来源映射；锁定价格、范围与币种，能从预算行回到相关图元，估算项显示计算依据。 |
| 后续 | “两扇窗对称，床边留出指定通道” | arrange。先复用前两批的定位、测量和预演，再增加组合规则。选择性撤回涉及依赖冲突，首版只承诺整次操作撤销。 |

单点编辑首版选矩形单层、明确共享墙段；歧义、多墙相交和无法保持门窗归属时给出可选项。其余项目仍可走原编辑器。语音工具声明选一个规范源生成客户端与 Go 的版本化清单，CI 比对名称、参数、风险与单位；支持旧客户端能力子集。小模型逐工具启用，先只读；写入准入要求包含真实哈语、俄语和混说的对象指代、数字、纠正和拒绝用例。

## 性能与可靠性

- 分别记录录音结束、STT 完成、首个可见候选、试改完成、提交、自动保存、首句播报。用同一操作 ID 关联，默认仅记耗时、大小、状态与模型版本。记录每任务模型调用次数、上下文字节、token 和完成率，防止省一次调用却增加返工。
- 第一轮沿用现有上下文与几何缓存；比较各步骤耗时后才引入增量。优先用一次语义工具在本地完成“定位→试改→测量”，避免模型在毫米坐标间往返。若场景传输成为瓶颈，再发 revision 和对象差量；服务端缺基准时可重取全量。
- 拖动时只需最新的局部预览，丢弃过期预览，最终落点必做完整校验。相机、选择和语音波形变化不触发预算计算。改地区价只更新估价；改窗宽要更新门窗量、相关墙面和预算。每项增量优化用完整重算作一致性对照。
- 平时使用当前及一个候选的有界缓存，离开项目释放。只在 profile 证明持续掉帧后评估后台计算；将消息复制、预热、取消和峰值内存一起测。Web 单独测浏览器主线程与 Canvas 路径。
- 对 60 Hz 目标设备，以构建与栅格时长分别 p95 ≤16.7 ms 作为初始门槛，同时观察超预算帧比例和 p99。语音交互另设建议目标：转写已完成后到首次可见反馈 p95 ≤1.5 s；按设备、网络、提供商分组。各目标都是验收预算，需先建立真机基线。
- 正确性门槛：硬条件违例却返回成功、版本过期后提交、重复执行、失败留下半套复合修改，在回归集上均为零。同一图纸和价格版本各出口按统一舍入规则一致。性能变快不能抵消这些失败。

## 实施顺序与退出条件

| 阶段 | 可独立交付的改动 | 放行依据 |
|---|---|---|
| 0 · 诊断和基线 | 缩减 AOT 崩溃样例；在 Android 中端机、iPhone、Web 记录典型与大图；打通分段计时 | 有可重复基线、崩溃影响范围和处置结果；大图画墙路径通过发布构建验证 |
| 1 · 统一预算与快照 | 统一项目币种、地区、价目版本和范围；水电暖按分项标示设计完成度；建立公开快照字段契约 | 预算页、语音、PDF和对外估价一致；只画插座时给排水仍可见为暂估；另一账号能打开约定范围内的图 |
| 2 · 一条完整语音改图路径 | 找墙、量墙、局部移动、3D 看结果、一次撤销；复用 transaction 在副本执行 | 任一步失败不写入，手改或切项目后迟到结果被拒；旧项目、旧网关和触控入口仍可用 |
| 3 · 多轮方案与本地价格 | 项目级设计要求、候选比较与造价归因；界面展示听到的条件和明显的取舍 | 固定 10 × 13 米项目完成两套符合约束的方案，价格差额能追溯；保存重开与师傅端版本对应 |
| 4 · 数据驱动优化 | 对照真实语句决定小模型只读分流；对真机热点局部优化 | 每次只改一个变量，以任务成功率、延迟、费用和资源峰值比较；按工具或客户端版本回退 |

每阶段采用可独立关闭的入口，新旧项目先双读，新字段按需写。发布前用旧版文件、恢复备份、两端版本错配、断网重试和提交时切后台走一遍。先验证旧应用能否保留新字段；若旧应用重存会丢失设计要求，需版本门禁或明确只读打开。对外快照固定发布时版本，修订后另存并关联原报价。

## 对计划的自审及修订

1. 曾考虑新建独立设计服务。引擎已支持事务与本地离线，重复实现几何会引入一致性成本。修订为客户端执行，Go 继续承担对话和协作。
2. 曾考虑全面预算缓存和后台线程。已有几何时估价约 0.2 ms，大图切分预览约 10.8 ms。优先量端到端，优化有证据的交互热点。
3. 对任意复合口令逐步执行再统一撤销，会在中途失败或自动保存时泄露半成品。修订为设计编辑在副本试跑，对外发布单独确认并去重。
4. “一键分享完整项目”可能包含私人数据。改为公开快照白名单并测试可见性；另将可还原性作为验收，避免图纸丢失算量依据。
5. 只拿一套户型或同一作者写的语句验收会高估成功率。保留个人住宅作为贯穿示例，另测凹形、两层、狭小、旋转朝向、歧义指代和混语；分别统计任务完成、指错对象和人工接管。
6. 全功能选择性撤销、全类型约束求解和端侧模型全面接管均扩大首版工作量。第一版仅交付明确墙段上的闭环；依据真实任务失败记录扩充能力。

## 最终交付顺序（设计编辑器）

1. 先交付三个低风险入口：按房间测净面积与最窄净宽、按两个房间定位共同墙段、语音切换平面/外观/指定房间漫游/预算。复用当前楼层已推导的几何、原有选择与相机逻辑。重复房名走消歧，多段共享墙返回各段坐标。轴线长和完成面净长分别标注。
2. 在第一批接口上增加墙段端点标注和局部移墙预演。校验门窗归属、连带房间、硬约束和图纸版本，再提交一次。失败的复合操作写入次数为零。
3. 连续语音会话支持打断与纠正；再补等距门窗和贴墙家具。用真实哈语、俄语、混说各自记录对象定位错误、人工接管次数和首次高亮延迟。
4. 将造价上下文与可分享快照统一；在同一地区价版本上显示改图前后差额。大图 AOT 崩溃调查、低端真机 profile 与兼容性回归作为发布门槛，单独核实。

首批实现验证：design.measure_room、design.locate_shared_wall 与 editor.view 已接入编辑器和网关清单。语音场景构造每次请求只取一次；按楼层缓存房间和轴线边索引。桌面 JIT 微基准逐层比较输出文本，16 房与 72 房示例共四层文本相同；72 房示例的两层每次构造从 1.50 / 1.49 ms 降至 1.00 / 0.97 ms（每层 20 次预热，300 次取均值）。尚未测量完整录音到屏幕反馈延迟。

局部移墙已接入预演与确认：指定获得空间和让出空间的两个房间、移动毫米数，以及可选的让出方最小净面积。预演在原平面标出目标墙线并显示两侧净面积，用户可触控确认或在下一轮语音中确认。预览标识一次有效，手动改图即失效；提交沿用编辑器历史与自动保存。
