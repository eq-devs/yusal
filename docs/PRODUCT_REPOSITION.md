# Yusal 产品重定位：围绕“我设计的房子”的社交与工作平台

## 1. 定位

一句话：**自己设计房子 → 发出来给大家看 → 收到评价 → 为这栋房子找人建 → 工人 / 包工头 / 工程师围绕这些房子接活。**

设计工具是入口，不是全部。平台上的一切对象都挂在“一栋具体的房子”上：

| 对象 | 挂在房子上的方式 |
| --- | --- |
| 作品（HousePost） | 一个设计的公开快照：平面图、面积、层数、房间数、预估造价、说明 |
| 点赞 / 评分 / 评论 | 对作品本身；工程师和施工方的评论带角色标签 |
| 需求（招人 / 承包） | 从作品一键发布，工程量从设计里自动带出 |
| 报名 / 报价 / 合作 / 评价 | 沿用原有流程，入口变成“这栋房子在招谁” |
| 入驻名片 | 工人 / 包工头（施工队） / 工程师（设计师）三种角色 |

旧版首页是“找活 / 找人”，把平台做成了招工网；现在招工是房子页面上的一个动作，接活大厅降为一个入口。

## 1.1 2026-11-04 优化补充

- 项目里的“发布作品”与“找施工方”独立，未公开设计也可直接询价；不从“以房子为中心”推导出必须公开作品。
- 游客继续可以离线编辑、保存和导出。公开作品、发布需求和分享文件采用不同动作。
- 四栏保持“首页 · 项目 · 消息 · 我的”，找人／找活在首页次级入口可达。
- 平台模拟数据及模拟备份须清楚标识；本地设计文件独立持久保存。
- 本轮不加入真实后端、支付、关注关系或更换 3D 引擎。

## 2. 参考了什么

- **Airbnb**：卡片型信息流（大图 + 一行事实 + 评分），底部固定操作条，搜索胶囊与筛选胶囊，大标题。
- **Houzz**：以“项目/房子”为中心的作品页，专业人士在作品下评论并露出身份，由作品引流到找专业人士。
- **Pinterest / 小红书**：首页先看别人的，再被“设计我的房子”按钮带去创作；点赞收藏是最轻的互动。
- **Behance**：作品页上“数据 + 故事 + 评价”三段结构，作者卡片固定在故事上方。

只借视觉语言与信息结构，不借任何素材。

## 3. 视觉

- 主色：胡桃木棕 `#A3673B`，底色暖米白 `#FFFCF8`，面板 `#F6F0E8`，墨色 `#2B2118`。
- 夜间：深木色底 `#15110E`，面板 `#201A15`，主色提亮为 `#D28B5A`，文字 `#F3EBE2`。所有颜色走 `YTokens`，夜间模式跟随“我的 → 外观”（自动 / 日间 / 夜间）。
- 头像、占位封面也改为木、草、陶土、石板等土壤色系。
- 设计工具本身保留原来的制图配色，不受影响。
- 字体：界面用 **Onest**（几何无衬线，完整覆盖哈萨克语和俄语西里尔字母），大标题和房子名用 **Lora**（暖色衬线，建筑 / 家居编辑物的气质，同样覆盖哈语）。中文回落到系统字体（PingFang / Noto Sans SC）。两者都是 OFL 开源字体，随应用内置，不依赖网络。

## 4. 交互原则

- 首页一屏只有三件事：看房子、搜索筛选、“设计我的房子”。
- 房子页从上到下：大图 → 标题与事实 → 作者 → 故事 → 设计数据 → 这栋房子在招谁 → 评价。访客底部一条固定操作：有需求就“去报名 / 报价”，没有就“我能建这栋房子”（私信）。
- 发布设计只填标题、说明、地区、标签、是否欢迎施工方，其它全部从设计里算。
- 入驻只是选角色再填名片，不做审核门槛；信任靠作品下的评论和合作后的评价。

## 4.1 分享

- 每栋发布的房子都有公开链接 `https://yusal-web.web.app/#/h/<id>`，房子页右上角“分享”可复制或发到 WhatsApp / Telegram。
- 任何人打开链接都直接看到房子页，不需要登录；登录只在点赞、评论、报名、私信时才要求。从链接打开时左上角是“首页”按钮。

## 5. 底部导航

首页（作品流） · 项目（我的设计 / 我发布的需求 / 合作） · 消息（聊天与通知） · 我的（我的房子、入驻、接活大厅、设置）。

## 6. 还没做的

- 作品照片（实景、施工过程）：现在只有平面图快照。
- 关注 / 粉丝、评论回复。
- 工程师的付费图审，包工头的“承建这栋房子”整包报价模板。
- 数据仍是内存模拟；真实后端按 `PostRepository` 接口实现即可。
