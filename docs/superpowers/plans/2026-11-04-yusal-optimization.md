## 一、建议采用的产品方向

**以房屋项目为中心：看房子 → 设计自己的房子 → 按需展示或找人建设。**

保留当前作品首页，因为这是已经实现的最新方向。让找施工方和找活有清楚的入口，但不要求先公开作品才能发布施工需求。

比较过三种方向：

| 方向 | 收益 | 代价 | 本轮结论 |
| --- | --- | --- | --- |
| 纯设计工具 | 聚焦画图与导出 | 已有找人与合作能力被边缘化 | 不采用 |
| 招工市场优先 | 找活入口直接 | 需重做首页，弱化房屋设计特色 | 暂不采用 |
| 房屋项目中心 | 延续现状，连接设计、展示、施工 | 必须区分三种对象和动作 | 推荐 |

以上是我的建议，尚不代表用户已经确认。

## 三、用户能看到的变化

### 3.1 导航与入口

保留四栏：**首页 · 项目 · 消息 · 我的**。本轮不移除独立消息栏。

| 页面 | 主任务 | 具体调整 |
| --- | --- | --- |
| 首页 | 看房屋与发现灵感 | 保留搜索、地区筛选、房屋卡片；排序收敛为一个控件；“正在找施工方”筛选保留 |
| 首页次级入口 | 找专业人士或找活 | 提供一个“找人／找活”入口，复用接活大厅；不与新建设计同时使用多个悬浮主按钮 |
| 项目 | 继续自己的建房事项 | 保留设计／需求／合作子页；新建设计为主要动作，显示项目最近更新时间 |
| 设计项目菜单 | 决定设计的下一步 | 分别提供“编辑设计”“发布作品”“找施工方”“导出”“备份” |
| 房屋详情 | 理解房子并行动 | 顺序为预览、面积等事实、作者说明、招募、评论；底部按房主／访客显示相应动作 |
| 消息 | 处理沟通和待确认事项 | 会话与通知分组，未读状态一致，跳转后保留可返回路径 |
| 我的 | 管理身份与偏好 | 名片、接活、作品、设置分组；开发者工具仅演示／调试模式可见，审核入口按权限显示 |

哈俄文案按语义翻译后检查长度，不直接机械替换所有“设计”字样。编辑器里的“设计”仍是准确概念。

### 3.2 三条流程必须独立可用

1. 本地设计：新建设计 → 编辑 → 保存／导出，不要求登录。
2. 展示作品：选择设计 → 确认公开内容 → 发布作品；不自动发布招工需求。
3. 找施工方：直接发布需求，或设计 → 选择施工范围 → 确认工程量与公开附件 → 补充条件 → 预览发布；不强制公开作品。

分享、作品发布、施工需求发布使用不同文案。发布前展示附件预览；完整 `.house` 文件与私人备注不因发布需求而自动公开。

### 3.3 视觉与交互

- 保留胡桃木棕、暖米白和 Onest / Lora，先改善层级与留白，不重新换品牌。
- 卡片突出预览、标题、地区、面积；造价标注“估算”，无评价时显示“暂无评价”。
- 统一页面边距、按钮高度、圆角和表单错误样式；主要触控目标至少 48 逻辑像素。
- 手机以单列为主；宽屏沿用响应式网格，详情限制阅读宽度。编辑器保持独立制图布局。
- 加载、无结果、尚无内容、失败分别呈现；已有数据刷新失败时保留内容并提供重试。
- 表单提交中禁用重复提交；登录取消不丢失输入；有未保存内容返回时提供保留或放弃选择。
- 演示模式常驻轻量标识，模拟登录、备份与分享操作处解释实际边界。

## 四、范围与约束

- 本轮交付是前端体验、可靠性和维护性优化，依然使用 MockBackend；不宣称上线可运营。
- 不新增关注、短视频、支付、托管、材料商城、付费图审或 AI 画图。
- 不更换 3D 引擎，不修改房屋几何算法，不改变 `.house` schema。
- 不全面迁移 Riverpod。先稳定现有异步加载机制；局部迁移需有明确收益。
- 不增加依赖，除非实测问题确实无法用现有能力合理解决，且在执行进度中说明原因。
- 不删除历史产品文档；明确历史状态和现行文档入口。
- 不自动提交、推送、发布到 Firebase 或更改线上数据。
- 保留中文、哈语、俄语设置及日夜主题，保护原有离线设计与导入导出。

## Review Focus

1. 登录取消或切换账号：表单保留，旧账号的列表和缓存不泄露给新账号（任务 2、4）。
2. 快速输入与乱序网络响应：只显示当前筛选的结果，离开页面后不更新已销毁组件（任务 4）。
3. 存储容量不足或索引／预览写入失败：不能错误提示保存成功，原设计仍可恢复或导出（任务 5）。
4. 分享链接目标不存在或不可见：明确不可用并能回首页，不能暴露非公开数据（任务 3）。
5. 小屏、俄语长文案、放大字体与暗色：主要操作可见且没有阻断操作的溢出（任务 3）。

## 六、真实后端：下一阶段单独立项

真实多人平台必须有后端，但将它混入本轮 UI 优化会掩盖工作量。完成本轮后再做单独技术方案，选择供应商与部署方式。

建议接入顺序：账号及服务端授权 → 作品／资料／图片 → 需求与版本快照 → 报名报价与双方合作确认 → 消息通知 → 云备份与冲突恢复。

上线前的硬性验收：跨设备读取同一份数据、服务端验证权限和状态转换、重复提交幂等、共享附件隐私、撤销分享、备份恢复、失败重试。客户端 Mock 中的权限判断不能代替服务端权限。
