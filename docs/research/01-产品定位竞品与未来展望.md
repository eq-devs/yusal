# Yusal 产品定位、竞品与未来展望

Nov 3, 2026 · @e

## 一句话结论

Yusal 最有机会的位置不是“又一个家装 3D 设计软件”，而是**面向哈萨克斯坦及中亚（以及中国农村）自建房家庭的“盖房全流程工具”**：从画图、算钱、算采暖、宅基地布置，到把图纸发给施工队、按阶段管进度。现有代码已经把“设计 + 预算 + 施工管理”打通，这是酷家乐、Planner 5D 等竞品都没有覆盖、而本地服务平台（Naimi.kz、Kaspi 广告）又做不了设计的空档。社区与工人平台应作为第二阶段，在设计工具积累了真实用户和真实项目之后再接入。

## 一、产品现状（基于仓库 eq-devs/yusal）

仓库是一个 Flutter 应用（Web / iOS / Android），README 自称“自建房设计工具”，版本 0.4.0（功能已到 README 中的 v0.7）。已实现的能力可以分成四层：

| 层次 | 已实现 | 说明 |
| --- | --- | --- |
| 设计（简易 CAD） | 长宽建外形、拉线分房、拖矩形挖房间、L/T/U 缺角、门窗拖到墙、楼层、三种楼梯、平/双坡/四坡屋顶、家具（含哈萨克传统织物：кілем、тұскиіз、көрпеше、сандық、дастарқан） | 刻意“不暴露 CAD 概念”，面向非专业用户 |
| 可视化 | 2D 施工风格平面（承重墙斜线、尺寸链）、3D 外观（日照、夜景、剖切、地基）、室内漫游 | 3D 为软件投影，生产级引擎尚未选定 |
| 工程计算 | 工程量、预算（¥/₸ 两套示例单价）、保温与热负荷（EN ISO 13370）、锅炉功率与燃料、水电暖点位与管线长度、条形基础 | 这是同类消费级软件几乎都没有的部分 |
| 落地施工 | R01–R10 设计检查与构造检查、宅基地布置与间距检查、九阶段施工进度与花费、A4 整套图纸 PDF / PNG 导出 | 导出明确写着“发给施工队” |

界面语言为**哈萨克语和中文**，首页内置“哈萨克乡村住宅 10×13”模板。数据全部存在本地 `.house` 文件中，**目前没有账号、云端、社区或工人市场**。项目话题里提到的“社区平台”和“工人”功能还停留在设想阶段。

## 二、产品定位

### 目标用户

1. **核心：自己出钱、自己找人盖房的家庭**。哈萨克斯坦农村和城郊的个人住宅（ИЖС）、新疆及中国农村自建房。他们没有建筑师，通常拿一张手画草图或“别人家的房子”去找施工队。
2. **次要：小型施工队、包工头、乡村建筑师**。需要快速出一套能看懂的图、报价和材料单。
3. **后续：建材商、工匠（瓦工、电工、暖气工）**。作为平台的供给侧。

### 市场规模（哈萨克斯坦）

- 2024 年全国交付住宅 1,896 万 m²、172,089 套，其中**个人住宅 39,064 套，约占套数的 23%**（[Adyrna](https://adyrna.kz/post/225835)）。
- 2025 年实际交付创纪录的 2,010 万 m²，2026 年计划 1,850 万 m²（[哈萨克斯坦政府](https://primeminister.kz/en/news/2026-zyly-kazakstanda-185-mln-sarsy-metr-turgyn-ui-salu-zosparlanuda-31158)）。
- 换句话说，每年约有 **4 万个家庭在盖自己的房子**，每户都要经历设计、预算、找人、买料、施工的完整流程，且采暖（严寒气候）和预算是最痛的两个点。这是一个足够专注、竞品空白的起点市场。

### 差异化

| 维度 | Yusal | 主流家装设计软件 |
| --- | --- | --- |
| 场景 | 从零盖整栋房子（地基、墙体、屋顶、院子） | 已有房子的室内装修、摆家具 |
| 输出 | 施工队能用的图纸 + 工程量 + 预算 + 进度 | 效果图、渲染图 |
| 工程 | 热负荷、锅炉、燃料、基础、间距检查 | 基本没有 |
| 本地化 | 哈萨克语、₸ 单价、乡村建筑习惯和传统家具 | 英文/俄文/中文，城市公寓为主 |
| 门槛 | 刻意隐藏 CAD 概念，手机可用 | 专业版复杂，消费版只做装饰 |

**定位表述建议**：“帮自建房家庭把房子先在手机上盖一遍：画得出、算得清、交得了施工队。”

## 三、竞品版图

### 1. 消费级家居设计 / 简易 CAD（国际）

| 产品 | 特点 | 与 Yusal 的关系 |
| --- | --- | --- |
| Planner 5D | 全球用户量最大的消费级 2D/3D 家居设计之一，近年主推 AI 生成平面与“空间 AI” | 设计体验和素材库强，但没有结构、采暖、预算、施工管理；无哈萨克语 |
| Floorplanner、RoomSketcher、HomeByMe、Live Home 3D、Sweet Home 3D | 画户型、摆家具、出效果图 | 同上，偏室内与房产展示 |
| magicplan | 手机扫描测量出平面图，面向装修承包商，含估价 | 扫描已有房屋，不适合从零盖房；但其“承包商报价”模式值得借鉴 |
| Maket.ai 等 AI 平面生成器 | 输入需求自动生成户型 | 2026 年的主要技术趋势，可作为 Yusal 的功能方向而非直接对手 |

### 2. 中国家装设计平台

| 产品 | 特点 | 与 Yusal 的关系 |
| --- | --- | --- |
| 酷家乐 | 国内最大的云设计平台，面向设计师与家居企业（B 端），渲染快、素材全，也有面向普通用户的 App | 城市精装修、全屋定制为主，商业模式靠企业订阅；不覆盖农村自建房结构与施工 |
| 三维家、打扮家 | 同类 B 端家装设计 + 定制家具生产对接 | 同上 |
| 各类“农村自建房图纸”网站/小程序 | 卖现成图纸、效果图，部分提供设计服务 | 内容是静态图纸，用户不能修改，也不算预算和采暖。Yusal 的“可编辑模板”是更好的形态 |

### 3. 哈萨克斯坦本地服务与建材平台

| 产品 | 特点 | 与 Yusal 的关系 |
| --- | --- | --- |
| Naimi.kz | 全国家庭服务撮合（维修、保洁、搬运等），50 万+下载，商店评分 4.9；但师傅需付费才能接单，文字评论平均仅 2.9 分，抱怨收费（[应用资料](https://mwm.ai/apps/naimi-kz/1028949260)） | 供给侧是“小活”师傅，不涉及设计和整房施工；说明本地有撮合需求，也说明“对师傅收费”容易引发不满 |
| Kaspi 广告（obyavleniya.kaspi.kz） | 全国最大的分类广告之一，大量“мастер ремонт”等服务广告 | 找人的事实标准渠道，但没有项目信息、没有图纸、没有信用体系 |
| 政府统一建设门户 Qportal.kz / E-Qurylys | 2026 年起整合规划、审查和施工监管，为项目分配唯一编号，建立持证施工企业登记（[Times of Central Asia](https://timesca.com/kazakhstan-to-launch-unified-construction-portal-in-2026/)） | 主要面向开发商和监管，未提及个人住宅。长期看是数据接口机会（持证施工企业名单、审批流程），而不是竞争者 |

### 4. 国际装修社区 / 承包商平台（参考模式）

| 产品 | 模式 | 可借鉴之处 |
| --- | --- | --- |
| Houzz | 灵感图片社区 + 专业人士目录 + Houzz Pro 承包商软件订阅 | 证明“社区 → 找人 → 给专业人士卖软件”这条路径可行 |
| Angi、Thumbtack | 按线索（lead）向服务商收费的撮合平台 | 撮合收入高，但服务商普遍不满按线索收费，与 Naimi 的问题一致 |
| 好好住、住小帮（国内） | 真实装修案例社区，再导向品牌与服务 | 内容社区可以低成本获客 |

## 四、竞争空档与风险

**空档**：没有一个产品同时做到“自建整栋房 + 本地语言和气候 + 预算采暖 + 施工交付”。设计软件不懂施工，服务平台不懂设计，政府门户不服务个人。Yusal 的“一个 `.house` 项目文件贯穿设计、预算、进度”正好是把这几块连起来的枢纽。

**风险**：

1. **大厂下沉**：酷家乐或 Planner 5D 加入 AI 生成整栋房子并本地化，体验上会有压力。应对是把本地工程知识（采暖、基础、乡村间距规范、单价库）做深，这是通用平台不愿意做的。
2. **用户付费意愿低**：自建房家庭一生只盖一次房，订阅制不成立。应把收入放在交易环节（工匠、建材、图纸审核），而不是软件订阅。
3. **准确性责任**：用户可能直接按预算和热负荷结果施工。需要明确“估算”属性，并提供“专业人士审核”作为增值服务。
4. **技术完成度**：README 写明 3D 引擎选型、真机性能、真实聊天软件中的文件分享仍未验收。俄语界面缺失也会限制哈萨克斯坦城市用户。
5. **冷启动**：工人市场是双边网络，供给和需求都要同时启动，难度远高于工具。

## 五、未来展望与路线建议

### 阶段一：把工具做成“盖房必备”（现在 \~ 6 个月）

- 补齐**俄语界面**（哈萨克斯坦城市和施工队普遍使用俄语）。
- 完成 3D 引擎选型和真机性能，确保 WhatsApp / Telegram 中 `.house` 和 PDF 分享顺畅，这是用户把图交给施工队的真实路径。
- 扩充**可编辑模板库**（不同面积、一层/两层、带地下室、带夏季厨房等），模板就是最好的获客内容。
- 单价库本地化到州/城市，并允许用户提交真实价格（为后续数据壁垒打基础）。
- 加入轻量 AI：根据家庭人口、预算、地块大小自动生成初始方案，然后用户手动改。这是 2026 年竞品的标配趋势，但 Yusal 可以生成“带预算和采暖的方案”。

### 阶段二：账号、云端与社区（6 \~ 12 个月）

- 云同步与“分享链接”：施工队和家人不用安装应用也能在网页上看图纸和预算。
- **真实案例社区**：用户发布“我家的房子”（设计文件 + 实拍 + 真实花费），别人可以一键复制为自己的模板。这比纯图片社区更有价值，也天然产生内容。
- 问答与经验：基础怎么做、冬季采暖烧什么最省等。

### 阶段三：工匠与建材市场（12 个月以后）

- **按项目找人**：用户把整套图纸和工程量发布为一个“项目”，施工队/工匠根据真实工程量报价。这比 Naimi、Kaspi 上的“一句话需求”信息量高得多，是 Yusal 的核心优势。
- **工匠作品集与信用**：工人完成的项目沉淀为带图纸的作品集和评价；可对接政府持证企业登记做认证。
- **材料清单直达建材商**：工程量自动变成询价单，按阶段采购。
- **收费建议**：避免像 Naimi 那样向师傅收“接单费”，优先考虑成交佣金、建材返佣、专业审图/设计师服务费，以及给施工队的专业版（报价、多项目管理）。

### 长期可能性

- 向乌兹别克斯坦、吉尔吉斯斯坦、蒙古等气候和建房方式相近的市场扩展（加入当地语言和单价）。
- 与银行和住房贷款机构合作：Yusal 生成的预算与进度可用于个人建房贷款的分阶段放款依据。
- 中国市场可作为第二个入口，聚焦农村自建房和新疆，但要面对酷家乐等更强的本土竞品，建议排在哈萨克斯坦之后。

## 六、待验证的假设

以下判断来自公开资料和对代码的阅读，还没有经过用户访谈验证，建议优先确认：

1. 自建房家庭是否愿意自己在手机上画图，还是更希望“选模板 + 小改”？
2. 施工队是否真的会使用导出的 PDF，还是只看总尺寸和预算？
3. 用户最愿意为哪一项付费：专业审图、找到靠谱施工队，还是更准确的预算？
4. 首发市场选哈萨克斯坦还是中国（新疆），决定了界面语言、单价库和推广渠道的优先级。
