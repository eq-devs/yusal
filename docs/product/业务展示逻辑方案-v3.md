# Yusal 业务展示逻辑重构方案（v3 草案）

日期：2026-11-04 · 状态：待确认 · 依据：产品文档 v2、PRODUCT_REPOSITION.md、`claude/project-thread-wuq5me` 分支 f0ea16d 的界面代码

## 1. 现在的问题

| # | 现状 | 带来的问题 |
| --- | --- | --- |
| 1 | 首页只有“别人设计的房子”作品流，悬浮按钮是“设计我的房子” | 产品文档里的两个入口只露出一个。“直接找人”（不画图也能发需求）在首页找不到；没设计的业主第一屏就不知道能干什么 |
| 2 | 工人 / 包工头只有首页一条横幅“看看谁在找人”，接活大厅又藏在“我的” | 供给方是平台的另一半，却要点两层才看到活；“找人（师傅列表）”同样被藏起来 |
| 3 | “设计”页分三个标签：设计 / 我发布的需求 / 合作 | 同一栋房子的设计、需求、报价、合作被拆在三个列表里，业主看不出“我这栋房子进行到哪一步了” |
| 4 | “我的”里堆了：我的房子、入驻、接活大厅、我的报名与报价、收藏、备份、设置、开发者工具、审核后台 | 一个页面同时承担身份、工作台、设置三种职责，像抽屉 |
| 5 | 房子页“为这栋房子找人”只是一段文字 + 按钮；访客按钮只有一个“去报名 / 报价” | 一栋房子往往同时招多个阶段（基础、砌墙、屋顶、水电），访客看不到具体在招什么、几个人报了价、报价截止到哪天 |
| 6 | 角色只在“入驻”时出现，界面对业主和师傅完全一样 | 师傅打开 App 先看到别人家的房子，而不是适合自己的活 |

## 2. 核心思路：一切挂在“一栋房子”上

把“房子”做成贯穿全部业务的主线对象，每栋房子走同一条进度线：

```
设计 ──► 公开展示 ──► 找人（需求） ──► 比价（报名 / 报价） ──► 合作 ──► 完工 & 评价
```

- **业主**看到的是“我的房子走到哪一步、下一步要做什么”。
- **师傅**看到的是“哪栋房子、哪个阶段在找我这种人”。
- **访客**看到的是“这栋房子长什么样、多少钱、谁在建”。

没有设计的需求（直接找人）也会生成一张轻量“房子卡”（只有地区、面积、类型，没有平面图），这样它在列表里和有设计的房子用同一种展示方式，以后补设计也能挂上去。

## 3. 信息架构（底部四栏）

| 底栏 | 回答的问题 | 内容 |
| --- | --- | --- |
| **发现** | 有什么房子？哪里有活？谁能干？ | 顶部三段切换：**房子** · **找活** · **找人**；共用一个搜索胶囊和地区筛选 |
| **我的房子** | 我的房子进行到哪了？我接的活怎样了？ | 顶部“待办条”+ 房子列表；有师傅名片的人多一个段落“我接的活” |
| **消息** | 谁找我？ | 不变：聊天 + 通知，点通知直达对象 |
| **我的** | 我是谁？怎么设置？ | 身份与名片、收藏、备份、设置、开发者 / 审核 |

“发布”不单独占一栏，而是右上角一个 **“＋”**，弹出三选一：

1. 设计一栋房子（进入设计工具）
2. 直接找人干活（不画图，选“招人 / 承包” → 填表）
3. 入驻接活（选工人 / 包工头 / 工程师 → 填名片）

这样产品文档 v2 的两个入口“直接找人”和“从设计找人”第一屏都能看到。

### 3.1 和现在的对照

| 现在 | 改为 |
| --- | --- |
| 首页（作品流） | 发现 → 房子 |
| 首页横幅 → 接活大厅 | 发现 → 找活 / 找人（提到第一层） |
| 设计 → 设计 / 我发布的需求 / 合作 三个标签 | 我的房子：每栋房子一张卡，点进去是“房子工作台”，需求、报价、合作都在里面 |
| 我的 → 我的报名与报价 | 我的房子 → 我接的活 |
| 我的 → 接活大厅 | 移除（已在发现） |
| 悬浮按钮“设计我的房子” | 右上角“＋”三选一 |

## 4. 发现页

### 4.1 默认打开哪一段

| 用户 | 默认段 |
| --- | --- |
| 未登录 / 只有业主身份 | 房子 |
| 有师傅名片（工人 / 包工头 / 工程师） | 找活，且默认筛选为自己的工种和服务地区 |

用户手动切换后记住上次选择。

### 4.2 三段的卡片

- **房子**：平面图 + 地区 / 面积 / 层数 + 预估造价 + 作者 + 赞 / 评论；如果在招人，卡片底部加一条“正在招：砌墙 · 屋顶 · 3 个报价”。
- **找活**：需求卡（类型、阶段、工程量、预算、截止日、已报名数），左侧缩略图就是它所属房子的平面图，点卡片进需求详情，详情顶部能回到房子页。
- **找人**：名片卡（工种、地区、接活状态、合作次数、有效评价数、作品缩略图）。

### 4.3 首屏顺序（房子段）

搜索胶囊 → 筛选胶囊（最新 / 最热 / 评分 / 正在招人 / 地区） → 一条“你可能在找”提示（业主看到“没有图纸也能直接找人”，师傅看到“附近 N 个新需求”） → 作品流。

## 5. 房子页：从展示到需求到报价

房子页是整个平台的枢纽，从上到下：

1. 大图（平面图快照，以后加实景）
2. 标题 + 事实行（地区、面积、层数、房间、预估造价）
3. **进度条**：设计 ✓ · 找人中 · 施工中 · 完工（公开显示，不含金额细节）
4. 作者卡（私信）
5. 故事 / 说明
6. **这栋房子在招谁**：按阶段列出需求小卡，每张写“阶段 · 工程量 · 预算方式 · 截止日 · N 人已报名”，点进需求详情
7. 设计数据（工程量、造价明细，按公开设置显示）
8. **谁在建这栋房子**：已确认合作的师傅（经双方同意后公开），完工后显示他们的评价
9. 评论与评分

### 5.1 底部固定操作条（按身份变化）

| 谁在看 | 房子有在招的需求 | 房子没有需求 |
| --- | --- | --- |
| 房主 | “管理找人（3 个新报价）” → 房子工作台 | “为这栋房子找人” → 选阶段 → 发布 |
| 有名片的师傅 | “报价 / 报名”，有多个需求时先选阶段 | “我能建这栋房子”（私信作者） |
| 普通访客 / 未登录 | “收藏这栋房子” + “我也要设计” | 同左 |

报价金额只对房主和报价人自己可见，公开只显示报名人数。

## 6. 我的房子（业主工作台）

### 6.1 列表页

- 顶部**待办条**（只在有事时出现）：“2 个新报价待比较 · 1 份合作约定待确认 · 1 个需求明天到期”，点哪条直达。
- 每栋房子一张卡：缩略图、名称、当前阶段、一行下一步提示，例如“砌墙：4 个报价，去比较”“还没公开，发布后别人能看到”。
- 底部“＋ 新房子 / 直接找人”。

### 6.2 房子工作台（点进一栋房子）

顶部是 5 步进度线（设计 / 公开 / 找人 / 合作 / 完工），当前步高亮，下面分四个标签：

| 标签 | 内容 |
| --- | --- |
| 设计 | 打开设计工具、备份状态、发布或更新公开作品 |
| 找人 | 这栋房子的全部需求，每个需求显示状态和报名 / 报价数；“新增阶段需求” |
| 报价 | 按需求分组的报价列表 + “对比”，不可比时提示原因（单位、材料范围、版本不同） |
| 合作 | 这栋房子的合作约定、变更、结束、评价 |

现在散落在三个列表里的东西都按房子归到这里；没设计的需求归到它自己的轻量房子卡下。

## 7. 我接的活（师傅工作台）

有师傅名片的用户在“我的房子”顶部多一个切换：**我的房子 · 我接的活**。

“我接的活”按状态分组：

1. 待处理：被邀请合作待确认、需求已修改待重新确认报价
2. 进行中：已确认的合作
3. 已报名 / 已报价：等对方回复
4. 已结束：可评价、可加入作品

每张卡都带它所属房子的缩略图和名字，点进去先看到需求，能一键回到房子页。

## 8. 各角色看到什么（汇总）

| 场景 | 访客 / 未登录 | 业主 | 工人 | 包工头 / 施工队 | 工程师 |
| --- | --- | --- | --- | --- | --- |
| 发现默认段 | 房子 | 房子 | 找活（日结招人类优先） | 找活（承包类优先） | 房子（看设计、评论） |
| 房子页底部 | 收藏 / 我也要设计 | 管理找人 / 为它找人 | 报名 | 报价 | 评论（带工程师标签）/ 私信 |
| 我的房子 | 登录提示 + 设计工具可直接用 | 房子工作台 | 我接的活 | 我接的活 + 我的房子（可发分包需求） | 我接的活 |
| 能发什么 | 不能（登录后可） | 设计、需求 | 名片 | 名片、分包需求 | 名片、设计 |

一个账号可以同时是业主和师傅，界面按“有没有名片 / 有没有房子”显示对应段落，不需要切换身份。

## 9. 登录时机

浏览、设计、粗估不用登录。以下动作才要求登录，登录后回到原来的操作：点赞、评论、收藏、私信、发布需求、报名、报价、备份、入驻。

## 10. 界面与交互（UI/UX）

### 10.1 视觉层级规则

- 每屏只有一个主操作，用胡桃木主色实心按钮（`YTokens.accent`）；次操作一律描边或文字按钮。
- 三级字号：页面大标题 Lora 26–28、卡片标题 Onest 16 半粗、辅助信息 Onest 13 灰（`muted`）。数字（面积、造价、报价数）用半粗，让人扫一眼就能比较。
- 卡片：圆角 16、图片 4:3 占卡片上半部、无边框，靠留白分隔（列表间距 24–28）。状态用小胶囊标签（找人中 = 主色浅底，施工中 = 草绿浅底，完工 = 石板灰浅底）。
- 底部固定操作条：白底 + 顶部细分隔线，左边一行摘要（如“3 个报价 · 截止 11 月 20 日”），右边主按钮，Airbnb 预订条的样式。
- 宽屏（≥700）：发现页两到三列网格；房子页左内容、右侧吸附操作卡（代替底部条）。

### 10.6 我接的活

分组标题 + 卡片，待处理组置顶并用主色标出；每张卡左侧房子缩略图、右侧“需求名 · 我的报价 / 报名状态 · 对方最后动作时间”，右侧箭头。已结束组卡片上有“写评价”“加到作品”两个文字按钮。

### 10.7 交互细节

- 所有列表卡片整卡可点，次要动作（赞、收藏）用图标点击区 ≥ 44pt，不和整卡点击冲突。
- 状态变化（报价被查看、被邀请合作）在卡片上用小圆点提示，进入后消失，和消息页未读数一致。
- 返回路径：需求详情顶部一行“属于：草原边的两层木屋 ›”，任何业务页都能一键回到它的房子。
- 需要登录的动作弹底部登录面板，登录后自动继续原操作，不跳离当前页。
- 夜间模式、三语、大字体沿用现有 `YTokens` 与 l10n；新文案三语同时补齐。

## 11. 实施顺序（确认后）

1. 底栏改为 发现 / 我的房子 / 消息 / 我的；右上角“＋”三选一。
2. 发现页三段切换（复用现有作品流和接活大厅页面），按名片决定默认段。
3. 房子页：进度条、按阶段的需求小卡、按身份的底部操作条、“谁在建”。
4. 我的房子：待办条、房子卡（按 projectId 归并需求和合作）、房子工作台四标签。
5. 我接的活：从“我的报名与报价”和合作记录合成。
6. “我的”瘦身：去掉接活大厅和我的报名。
7. 补测试：底栏、发现默认段、房子页按身份的操作条、工作台归并逻辑；三语文案。

数据层不需要改接口：需求已有 `designProjectId`，作品已有 `projectId`，归并在界面层做；“谁在建”需要一个“合作方同意公开”的字段，先在 mock 里加，真实后端按同一接口实现。

## 12. 需要你确认的选择

1. **底栏**：发现 / 我的房子 / 消息 / 我的（推荐），还是保留现在的 首页 / 项目 / 消息 / 我的、只在首页加三段切换（改动更小，但业主仍看不到“我这栋房子到哪步了”）。
2. **师傅默认看找活**：有名片的人打开发现默认进“找活”（推荐），还是所有人都先看房子。
3. **报价公开程度**：公开只显示报名人数，金额只给房主看（推荐），还是公开报价区间。
