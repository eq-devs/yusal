# v0.5 易用性优化记录

日期：2026-10-08。每轮一个具体任务：先在真实浏览器操作现有流程，再改、再测、再回到浏览器核对。

浏览器验证方式：本机 `flutter build web --release` 产物，用系统 Chrome（无头，Playwright 驱动）打开。手机场景为 390×844、触摸事件（CDP `Input.dispatchTouchEvent`）；桌面场景为 1280×800、鼠标与滚轮。截图逐张人工查看。这是真实浏览器中的指针/触摸事件，但不是真人、不是实体手机。

## 第 1 轮：建第一面墙、接墙、改墙（P0）

### 实际操作发现的问题（改动前）

| # | 触发步骤 | 影响 |
|---|---|---|
| 1 | 从 ＋ 往下拖墙 | 长度标签画在起点，被大 ＋ 和手指同时挡住，拖动中看不到长度 |
| 2 | 拖到离下墙约 1.2 米处松手 | 墙悬空、房间没被分开，界面没有任何“未连接”提示 |
| 3 | 底部 ➕ 压住“宽 12.00 米”尺寸；房间色块有细缝 | 读数困难，画面不干净 |
| 4 | 提示文字中的 ➕ emoji 首次显示为方块 | Web 端依赖在线 emoji 字体，网络差时一直是方块 |
| 5 | 长按墙体 | 底部整屏菜单，离墙远、纯文字、删除不醒目 |
| 6 | 点墙（实际点在墙上的 ＋ 上）再拖墙身 | 被当成“选起点”，拖动变成新建一段 1.5 米短墙（误建） |
| 7 | 墙体模式下单指拖空白处 | 不能平移画布，只能双指 |
| 8 | 移动隔墙 | 丁字相连的墙不跟随，连接被拆开 |
| 9 | 新增空层 | 不切换到新楼层，名称“一楼 / 2楼”不一致 |
| 10 | 撤销、删除 | 没有反馈；撤销后 ＋ 起点停在已不存在的墙端 |
| 11 | 放大画布 | 房间文字跟着放大到占满屏幕 |
| 12 | 在较矮窗口显示首次引导卡片 | 卡片盖住顶部 ＋，手指按不到（改动中发现） |

### 参考资料（看过资料，未实际操作这些产品）

- Sweet Home 3D 用户指南：绘墙时有提示框和对齐线，角度按 15° 吸附，精确长度用回车输入（移动版不支持）。
- Live Home 3D iOS 指南：拖动开始画墙、抬手结束、需点“完成”退出。
- Android 无障碍指南：触摸目标至少 48dp；WCAG 2.2 SC 2.5.8：至少 24 CSS px。

### 采用的方案（取舍）

- **手势分工固定**：拖 ＋ = 建墙；点墙（包括点在墙上的 ＋）= 选中墙；拖选中墙的两端 = 改长度，拖墙身 = 移动；拖空白 = 平移；双指 = 缩放。按住 ＋ 不放再拖仍是建墙，不弹菜单。比“点 ＋ 选起点”少一种隐含状态，误建墙消失。
- **连接吸附 + 明确状态**：末端在约 22 屏幕像素内遇到墙就接上，末端画圆环；顶部状态条实时显示“竖墙 6.00 米 · 已连到墙 / 末端没连墙 / 不能穿过门窗”。长度标签放在线段中部侧边，不在手指下。拖出房屋会停在外墙上。
- **就近菜单**：选中墙后菜单出现在墙的上方或下方（不遮墙），图标+文字：接墙、长度、位置、墙厚、删除（红色）。外墙为接墙、房屋尺寸、墙厚。底部工具卡不再重复这些按钮。
- **移墙保持连接**：新增核心命令 `MoveDrawnWall`，侧移时把“端点落在这面墙上”的墙一起伸缩；先伸长后缩短，房间名称不丢；穿过的墙、墙端沿着贯通墙滑动的情况不受影响；会把相连墙压到 0.30 米以下时拒绝并说明原因。整个移动一次撤销。
- **改长度保持连接端**：输入长度时固定已连墙的一端，移动自由端。墙厚提供 12/18/24/37 墙快捷选择。
- **反馈**：删除提示“已删除墙体 · 撤销”；撤销/重做有提示；新增楼层自动切过去并提示；Esc、Ctrl/⌘+Z、Ctrl/⌘+Shift+Z、Delete 键可用。
- **首次引导**：没有内墙时，工具卡内显示“按住任意绿色 ＋，往房子里面拖……”，画布上一个虚线箭头示范方向；建好第一面墙后自动消失。引导放在卡片里，不盖画布。

### 验证

- `flutter analyze` 无问题；`flutter test` 120 项通过（新增 `wall_move_test`、`wall_snap_test`、`wall_gestures_test`，更新 4 项旧界面断言：长按菜单从底部表单改为就近菜单、墙身斜拖改为按主方向锁定）。
- Chrome 手机尺寸触摸：建隔墙并吸附到对墙、丁字接墙、点墙出菜单、拖墙身移动且丁字墙跟随、按住 ＋ 再拖、空白平移、双指缩放、墙厚预设、删除后撤销，截图逐张核对。
- Chrome 桌面鼠标：鼠标拖 ＋ 建墙并吸附、滚轮缩放。

### 剩余问题

- 拖动中长度标签会压住房间文字（白底可读，松手后恢复）。
- 指北针画在可缩放画布里，放大后会移出视野。
- 滚轮一格缩放幅度偏大（InteractiveViewer 默认）。
- Web 端中文和符号字体仍从 Google 字体服务按需下载；在无法访问该服务的网络中可能显示方块，需另行内置字体（会增加数 MB）。

## 第 2 轮：门窗直接操作、房屋长宽、反馈与多端布局（P1）

### 实际操作发现的问题（改动前）

| # | 触发步骤 | 影响 |
|---|---|---|
| 1 | 在“墙体”模式放好门后拖门 | 拖动变成平移画布，门不动；只能退出墙体模式再拖 |
| 2 | 从工具卡拖门 | 拖动图标在手指右下方，盖住墙上的吸附预览；改成浮在手指上方后，箭头尖和真实落点又差 40 px |
| 3 | 门放歪（没落在墙上）松手 | 没有任何提示 |
| 4 | 点门 | 10 项纯文字列表，“距墙起点”默认填 0.20 米而不是当前值 |
| 5 | 调整 → 房屋尺寸 | 先弹表单再点“拖动外边框调整”才出现手柄，手柄图标是 ＋，像“添加” |
| 6 | 带“撤销”的提示 | 本版 Flutter 中带按钮的提示默认不自动消失，一直盖在工具卡上方 |
| 7 | 保存失败 | 只把 10 px 小字改成“保存失败”；不会自动重试 |
| 8 | 新建对话框 | “直接拖出外形”的图标像未勾选的复选框；校验文字出现内部概念“每格” |
| 9 | 横屏 844×390 | 两行顶栏 + 工具卡后，平面只剩约 80 px 高 |
| 10 | 3D 楼层滑块 | 显示“1楼”，与楼层名“一楼”不一致 |
| 11 | 鼠标悬停 | 光标不提示哪里可拖、可点 |

### 采用的方案

- 门窗在所有墙体工具中可直接拖动（选中墙时以墙为先，保留“改墙模式下可选带门窗的墙”）；点门窗打开属性。
- 工具卡拖出的门窗浮在手指上方，带“↓”箭头，**箭头尖就是落点**；状态条显示“已贴合墙面，松手放下门 / 拖到墙上……”。放下后提示“已放置门 · 可以直接拖动它调整位置 · 撤销”；没放上墙时说明原因。
- 门窗属性：标题写明类型和尺寸，各项右侧显示当前值，“距墙左端/下端”按墙方向命名并预填当前值，删除为红色并可撤销。
- 房屋尺寸：调整 → 房屋尺寸直接进入手柄模式，手柄改为双向箭头，卡片内“输入长宽”；拖动时显示“房屋宽 13.50 米 · 所有楼层一起改”。
- 提示统一浮在工具卡上方，带撤销的 6 秒后消失（顶栏撤销按钮一直可用）。保存状态改为图标+文字，失败变红、弹出说明并每 5 秒自动重试。
- 首次引导缩短为一行（“按住绿色 ＋ 往里拖，松手就建好一面墙”），窄屏单独一行，宽屏与状态同行。
- 宽度 ≥ 600 时顶栏合为一行；横屏平面高度约增加 50%。
- 鼠标悬停：＋ / 墙 → 手形，空白 → 抓手，选中墙身 → 移动，墙端与房屋手柄 → 双向箭头。
- 3D 楼层滑块显示实际楼层名；新建楼层按“二楼、三楼……”命名。

### 验证

- `flutter test` 121 项通过（新增保存失败重试测试；门窗拖放测试改为瞄准箭头尖）。
- Chrome 手机触摸：墙体模式中放门、拖门换位置、点门看属性；房屋尺寸手柄拖动；320×568 下引导、菜单、保存状态；844×390 横屏单行顶栏。
- Chrome 桌面鼠标：悬停光标通过页面计算样式读取（＋ 与墙为 pointer，空白为 grab）；2D/3D 切换。

### 剩余问题

- 320 宽手机上 6 个工具仍换成两行（与改动前相同）。
- 竖向很长的墙在小屏上，菜单只能盖住一部分平面（可点 ✕ 或点空白关闭）。
- 桌面 3D 提示仍写“单指旋转 · 双指缩放和平移”，未区分鼠标。

## 第 3 轮：数据一致性、大户型性能、刷新恢复与资源（P2）

### 检查与发现

| # | 检查方式 | 结果 |
|---|---|---|
| 1 | 随机序列测试：30 个种子 × 24 步，混合新建/移动/改长/删除墙和放门窗，第二层作为对照 | 545 次被接受的修改后，每步都通过校验、`.house` 编解码逐字节一致、原本正常的门窗仍正常、另一层完全不变、房间 ID 不重复 |
| 2 | 旧 v1 两层样板文件中移动由房间推出的内墙 | 自动升级为 v2，房间名称、门窗、另一层不变，可重新读写 |
| 3 | 30×24 米、36 房间、60 段墙、30 扇门、两层的大户型（导入 Chrome） | 拖动墙身时每次移动中位 68 ms、p90 267 ms，明显卡顿 |
| 4 | 剖析一次墙体预览（Dart VM） | 约 80 ms，其中约一半在“检查所有楼层的门窗”，而一次改墙只会影响本层；拖动中每次还重复校验同一份输入 |
| 5 | 大户型平面 | 小房间的名称、面积、尺寸三行文字溢出到墙和门上 |
| 6 | 编辑后 150 ms 内刷新页面 | 修改已保存（页面隐藏时会保存），但刷新后回到首页，需要重新找设计 |
| 7 | 横竖屏切换时墙菜单打开 | 菜单用上一帧的画布尺寸定位，跑到房子左边盖住平面 |
| 8 | 资源加载 | CanvasKit 从 www.gstatic.com、中文字体从 fonts.gstatic.com 按需下载（约 450 KB 中文字体子集） |
| 9 | 首页缩略图（无 GPU 的无头 Chrome） | 显示空白；开启 WebGL（SwiftShader）后正常，属于浏览器回退到纯 CPU 渲染时的情况 |

### 改动

- 核心：墙体命令只重算本层门窗状态并复用改动前结果；同一设计状态的输入校验按对象缓存（状态不可变）。单次预览约 80 → 48 ms（VM）。
- 编辑器：拖动时线段、端点和长度每次都更新；完整检查（含房间预览）在较慢时最多约每 100 ms 一次，手指停住时补一次，松手前一定按最终位置重新检查。
- Chrome 同一大户型拖动：中位 50 ms、p90 65 ms、最大 150 ms（改动前 68 / 267 / 297 ms）。同一测量方法在小户型上的基线为中位 34 ms（无头浏览器渲染与等待帧本身的开销），所以大户型额外开销约 17 ms。
- 房间标签按屏幕上的房间大小决定显示几行：先省略尺寸，再省略面积，最后不显示。
- 刷新或重启后自动回到正在编辑的设计；正常返回首页后不再自动打开；记住的设计已不存在时忽略。
- 菜单定位使用当前屏幕尺寸；长墙上下放不下时放在墙的侧边。

### 验证

- `flutter test` 126 项通过（新增随机序列、大户型、v1 移墙、刷新恢复测试）。
- Chrome：大户型导入、拖动计时与 CPU 剖析；编辑后立即刷新再打开；导出 `.house` 下载后在全新浏览器配置中导入，结果一致；横竖屏切换。
- iOS 模拟器（iPhone 17 Pro / iOS 26.4）原生集成测试 5 条全部通过（第 2 轮后与最终代码各跑一次）。

### 剩余问题 / 需要决定

- Web 版依赖 Google 的 CDN（CanvasKit 与中文字体），托管也在 Firebase。若面向无法稳定访问 Google 服务的网络，需要决定：改为本站托管 CanvasKit（`--no-web-resources-cdn`，多约 7 MB）并内置中文字体（数 MB），以及更换托管方。
- 大户型移动带多个相连墙的墙时，完整检查仍需约 50–150 ms，房间颜色预览会稍滞后于手指。
- 浏览器回退到纯 CPU 渲染时首页缩略图不显示（不影响编辑）。
