# Yusal UI/UX 下一轮建议

依据：当前代码、此前浏览器操作及用户提供的手机详情页截图；本轮尚未完成真机视觉验收。

## 核心判断

以「房屋项目」组织产品：看房屋 → 查看图纸 → 创建自己的项目 → 发布作品或找施工方。施工方需要快速看到地点、工程范围、预算、时间和图纸，再决定联系或报价。

## 优先调整

| 优先级 | 当前问题 | 建议 |
| --- | --- | --- |
| P0 | 无封面时巨大占位区域挤压内容 | 有图纸时用真实平面图作为封面；无图片时缩短占位，不使用空白大色块 |
| P0 | 图纸入口容易落在折叠区以下 | 标题、关键参数之后紧接图纸预览与「打开图纸」，先于作者故事和工程量 |
| P0 | 找人作品与正式需求状态混淆 | 无具体需求时主动作「联系作者」；已发布需求时「查看需求／报价」，避免点击「我能建」却只能私信 |
| P1 | 首页视觉信息分散 | 卡片突出图纸、标题、地点、面积与是否招募；评论、点赞、作者信息保持次级 |
| P1 | 项目操作都藏在菜单 | 项目卡片常显「继续设计」和「找施工方」，发布作品、导出、删除保留在菜单 |
| P1 | 施工需求详情先展示大封面 | 首屏突出工种、地区、预算、开工日期，再显示图纸和工作范围；底部只保留一个主动作 |
| P1 | 发布附件可见性难以理解 | 发布前提供「别人将看到什么」预览，分别显示图纸和工程量，不公开时说明对报价的影响 |
| P2 | 桌面端只是放大的移动页 | 宽屏详情左侧展示图纸，右侧固定核心信息与联系／报价操作；窄屏保持顺序布局 |

## 图纸体验

已有只读入口、缩放、楼层选择。下一步优先验证手机手势与尺寸文字清晰度，再考虑双击缩放、图纸页码、横屏适配。旧作品缺少图纸时不能补画虚构设计；应引导作者关联真实项目后重新发布。

## 验收方式

在 Pixel 8 Pro 上逐一检查：游客浏览、打开新发布图纸、楼层切换、缩放复位、返回、项目编辑、从项目发布需求。覆盖浅色／深色及哈语／俄语／中文；Web 另外检查窄屏和桌面。此文为下一轮建议，尚未将这些改动全部实施。
