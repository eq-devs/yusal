# Yusal MVP 平台功能开发计划书（mock 后端版）

依据：《Yusal 产品文档 v2：建房设计、施工找人与工程报价平台》（2026-11-03）。
本计划把文档第 13 节 MVP 范围拆成可连续实施的开发步骤。首轮实现中，所有后端数据都放在仓库接口（repository interface）后面，用内存 mock 实现；以后接入真实后端时，只需替换实现，不改界面与领域模型。

## 0. 不变的边界

- `lib/core/**` 纯 Dart 设计核心、`.house` 文件格式、渲染与本地存储边界保持不变。平台数据不写入 `.house`。
- 设计工具继续可独立使用，不登录也能打开、编辑、保存本地设计。
- 平台代码全部放在 `lib/platform/`：
  - `domain/`：纯 Dart 模型与业务规则（不依赖 Flutter），可单测。
  - `data/`：仓库接口 `repositories.dart`；`mock/` 内存实现，附种子数据、可注入时钟、模拟延迟和网络故障。
  - `snapshot/`：从 `HouseDocument` 生成发布快照（只读调用现有 `estimateCost`，不改核心）。
  - `ui/`：Airbnb 风格主题与全部平台页面。

## 2. 领域模型（`lib/platform/domain/models.dart`）

每个对象都有稳定 id；版本化对象保存完整历史。

- `Account`：手机号（默认隐藏）、验证状态、显示名、是否注销。
- `ServiceProfile`：个人/团队、名称、工种、服务地区、接活状态（现在可接 / 指定日期后 / 暂不接）与最近确认时间、经验、人数、参考价（金额 + 单位 + 适用范围）、作品（自主上传 / 平台合作，区分来源）。
- `Demand` + `DemandVersion`：类型（招人干活 / 找人承包）、状态（草稿、待审核、招募中、暂停、已找到人、已到期、已关闭、未通过）、公开地区与私密地址、时间（可待协商）、预算（区间 / 明确金额 / 请报价；人工与材料范围分开）、招人字段（人数、计酬方式、工资或面议、天数、食宿、工具、结算周期）、承包字段（整栋/阶段/自定义、工程量与来源、包工包料、开工、工期、报价截止）、发布者与项目关系（业主 / 分包）、设计快照引用、附件公开开关、分享链接与撤销。
- `Application` + `ApplicationVersion`：报名（到岗时间、期望工资或接受原条件、可提供人数、说明）或报价（依据的需求版本、范围、仅人工/包工包料、按量/总价/需现场确认、工程量单价行、工期、包含/不包含、有效期）。状态：已提交、已撤回、未选用、待对方确认、已形成合作；“待重新确认”作为标记。
- `Cooperation` + `Agreement`：双方、范围、依据版本、人数或承包内容、金额与计价、时间、付款节点、材料工具责任、待确认事项；每版记录提出人和确认人。状态：待双方确认、已确认、已结束、未成立；结束方式：双方确认、单方报告、取消、争议。
- `Review`：维度（按时付款/范围清晰/沟通/施工体验，1–5），可跳过，按公开规则显示。
- `Conversation` / `ChatMessage`：文字、图片（mock 占位）、需求卡片、报价卡片、系统消息；发送中/已发送/失败。
- `AppNotification`：新报名/报价、确认请求、约定变更、结束请求、评价、到期、结果回访、审核结果。
- `DesignSnapshot`：设计名、设计更新时间、提取时间、阶段、工程量行（名称、数量、单位、来源）、尺寸摘要、可选平面预览、公开开关。
- `BackupRecord`：项目 id、名称、`.house` 文本、备份时间、备份时本地更新时间。
- `Report` / 拉黑：举报对象、原因、处理结果、操作人与时间。

纯规则（`domain/rules.dart`）：状态转换表、报价可比性检查（版本、材料范围、计价方式、单位）、按量报价自动合计、评价公开判断、需求能否接收新申请等。

## 3. 仓库接口（`lib/platform/data/repositories.dart`）

`AuthRepository`、`ProfileRepository`、`DemandRepository`、`ApplicationRepository`、`CooperationRepository`、`ChatRepository`、`ReviewRepository`、`NotificationRepository`、`SnapshotRepository`、`BackupRepository`、`ModerationRepository`、`DictionaryRepository`。

约定：
- 所有方法异步，失败抛出 `ApiFailure(code, message)`。
- 写操作带 `requestId` 的地方保证幂等（重复点击不重复创建）。
- 权限与状态转换由“后端”（现在是 mock）校验，客户端不能直接把自己改成已录用/已验证。
- `changes`（`Listenable`）通知界面刷新；真实后端可用推送/轮询实现。

`MockBackend` 一个类实现全部接口，内存存储，注入 `Clock`（开发者工具可“快进 1 天/7 天”验证到期、单方结束、评价窗口、回访），延迟可设为 0 用于测试。

## 4. 界面结构（Airbnb 视觉语言）

主题：白底、#FF385C 珊瑚红强调色、#222 正文、圆角 12–16 卡片、柔和阴影、胶囊筛选条、大号粗标题、底栏细线图标。只借鉴视觉语言，不使用其素材与品牌。

底栏三项：
1. **发现**：顶部“找活 / 找人”切换；搜索栏 + 工种/地区/类型/可接状态胶囊筛选；需求卡片与名片卡片；右上角消息中心（未读角标）；“发布需求”浮动按钮。
2. **我的项目**：分段“设计 / 我发布的需求 / 合作”。设计页嵌入现有设计首页，每个设计增加“找施工方”（从设计发布）和“备份”入口。
3. **我的**：账号、我的名片（个人/团队）、我的报名与报价、收藏、备份与恢复、语言、隐私与安全（拉黑列表）、注销、开发者工具（切换测试账号、快进时间、模拟断网、审核后台）。

页面清单：登录（手机号 + 验证码，登录后回到原操作）、需求详情、发布向导（类型 → 工作信息 → 预算与时间 → 附件与隐私 → 预览）、从设计发布（选阶段 → 确认工程量 → 公开附件 → 补充信息）、名片编辑与主页、报名/报价编辑、报名报价管理、报价对比、聊天、合作详情（约定版本、确认、变更、结束、评价）、评价、消息中心、分享预览（公开网页视图）、备份冲突处理、审核后台。

## 7. 接入真实后端时要做的事

1. 选型（Firebase 或自建）后，为每个仓库接口写真实实现，`MockBackend` 留作测试替身。
2. 把 mock 中的权限与状态校验搬到服务端；客户端保留乐观提示。
3. 短信验证码、图片上传、推送、分享网页（Hosting）分别接入。
4. 数据持久化：mock 现在只在内存中，重启恢复种子数据。
